\## Дүгнэлт (debrief)



Хамгийн үр дүнтэй нь Couch Potato аялал байв: олон янзын, буруу оролтоор ном нэмж, хайж, устгаж явахдаа BUG-04 («Нийт ном» тоолуур хүснэгтийн мөрөөс 1-ээр илүү) болон BUG-05 (хайлт том/жижиг үсэг ялгадаг)-ыг олсон. Saboteur аялал API түвшинд BUG-11 (дутуу JSON-д 400 биш 200 OK буцаадаг)-ыг илрүүлсэн нь UI-аар огт харагдахгүй согог байсан тул энэ аялал өөр төрлийн согог олсноороо үнэ цэнэтэй. Хоосон Гарчиг/Зохиолчтой ном нэмэгдэх (BUG-01), он-ы шалгалт байхгүй байх (BUG-02), он таслалтай харагдах (BUG-03) зэргийг оролтын хилийн утгаар шалгахдаа олсон \*\*\[шалга: аль аялал]\*\*. Charter-аас гадуур санамсаргүй олдсон зүйл бол Устгах товч улаан биш ногоон өнгөтэй байх (BUG-07), урт гарчиг хүснэгтийг тэлэх (BUG-06), мөн буруу оролтод сервер 500 Internal Server Error буцаасан явдал юм. Эдгээрийг тусгайлан хайгаагүй, өөр зүйл шалгаж байхдаа анзаарсан. Дараагийн session-д шалгагдаагүй үлдсэн зүйлс: давхардсан ном нэмэхийг татгалзах эсэх, `<b>test</b>` зэрэг HTML оролтын аюулгүй байдал, үйлдэл бүрийн дараах мессежийн үсгийн алдаа \*\*\[шалга]\*\*. Мөн устгасны дараах тоолуурын зан төлөв, зохиолчоор хайх, API-ийн бусад endpoint-ууд (GET, DELETE) шалгагдаагүй, эдгээр нь дараагийн charter-ын сэдэв болно. Лаб 1-ийн Playwright автомат тестээр BUG-04 (мөрийн тоо ба тоолуурыг харьцуулах assert), BUG-05 (`clean`, `CLEAN` хайлтын үр дүн), BUG-01, BUG-02 (буруу оролтыг татгалзах эсэх) зэргийг найдвартай барих байсан, учир нь хүлээгдэж буй үр дүн нь тодорхой, шалгахад хялбар. BUG-11 болон 500 алдааг ч тестэд API хүсэлтийн статус код шалгаснаар автоматаар барьж болно. Харин BUG-07 (товчийн өнгө) болон BUG-06 (урт гарчигтай үед хүснэгтийн байршил эвдрэх) нь визуал шинжтэй тул зөвхөн хүний нүдээр олдох байсан, харин BUG-03 (1,999 гэх таслал) нь тусгайлан assert бичсэн тохиолдолд л автоматаар баригдана. Дүгнэж хэлбэл, автомат тест урьдчилан мэдэж байгаа дүрмийг шалгахад сайн, хүний судалгааны туршилт урьдчилан тааварлаагүй согогийг олоход сайн тул хоёр арга бие биеээ нөхдөг.
